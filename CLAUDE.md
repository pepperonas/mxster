**Audio format** (since v0.5.1): AAC-LC 96 kbit/s `.m4a`, cut at 4:00 with a 3 s fade, no metadata, `+faststart` — one place: `scripts/audio-hosting/encode.js` (`encodeForGame`, also a CLI that converts any leftover source file). The cut is safe because the random start lies within the first 2:30 (`RANDOM_START_MAX_S`). ## Architecture

### Access model (server/)
- `GET /api/auth/login` → Google → `GET /api/auth/callback`: ID token checked (`aud`, `iss`, `exp`, `email_verified`), user upserted. **New users start `pending`** and trigger a mail to `NOTIFY_EMAIL`; addresses in `MXTAPE_ADMIN_EMAILS` (martinpaush@gmail.com) are approved on the spot and can never be locked out.
- Statuses: `pending | approved | rejected | blocked`. Reject/block delete the user's sessions.
- `GET /api/session` → `{me: … | null}` (the client's source of truth, 200 even when signed out); `GET /api/me` (401 when signed out).
- **E-mail accounts** (`api/password_auth.py`, `passwords.py` scrypt from the stdlib): `POST /api/auth/register {name,email,password,lang}` → 202 always (a taken address gets a mail saying so, never an answer that reveals it); the account is `pending` with `google_sub = "pw:<random>"` and `email_verified_at` NULL (`User.unverified`). The link `GET /api/auth/verify?token=` (signed, 48 h = `VERIFY_TTL`, bound to a fingerprint of the current password hash so a later re-registration of the same unconfirmed address kills older links; single use — once confirmed it signs nobody in) confirms, signs in and only then mails the admin (unconfirmed sign-ups are no request: hidden from `/api/admin/users`, deleted after 48 h by `purge_unverified`, run on startup and on every register). `POST /api/auth/password-login` (wrong address and wrong password answer the same; `email_unverified` only after the right password), `POST /api/auth/resend` (needs the password), `POST /api/auth/forgot` → mail with `/reset-password?token=` (1 h, carries a fingerprint of the current hash = single use), `POST /api/auth/reset` (ends every session, confirms the address). Mails in de/en (`lang` from the client) via `mail.py`. A Google sign-in with the address of an e-mail account joins it (Google confirms the address; `upsert_user`); if that account was never confirmed, its password and sessions are dropped (pre-hijacking: a stranger may have registered the address first). Limits (never usable to lock the owner out): login counts only failures, reserved atomically before the password check and given back on success (`take`/`give_back` in `security.py`): 10 per address+IP, plus 20 per address across all IPs in 15 min — or 20 per device for a device holding `mx_known` (signed device id + `[user id, fingerprint of the current hash]`, so a password change retires it and a leaked cookie still only buys 20 guesses); mails per address (register, resend, forgot: 3/h) are throttled silently — the request still answers 202, only the mail is skipped. `me.hasPassword`, admin rows carry `method`.
- `/api/admin/*` answers **404** to everyone but admins (existence not revealed); every decision is logged in `admin_actions`.
- `GET|PUT /api/data/{history|achievements|settings}`, `DELETE /api/data`: per-account JSON documents with optimistic versioning (stale PUT → 409 + current document), 512 KB cap. Only for `approved`.
- `GET /api/auth/audio-check` → 204/401: nginx `auth_request` target, so `/audio/` is only served to approved sessions.
- Rate limit per IP on login/callback; `X-Real-IP` is trusted only from 127.0.0.1.
- Mail: SMTP (`SMTP_*`) or `SENDMAIL_PATH`; both empty = no-op. Sent in a background thread.

### Frontend flow
`App.tsx`: `MotionProvider → AuthProvider → AuthGate → AppProviders → AppShell → route`.
- `auth/AuthGate.tsx`: loading / offline / login / waiting room (pending, polls every 30 s + on tab focus) / closed door (rejected, blocked) / app. Nothing below the gate (incl. audio) loads before approval. A 401 or `not_approved` from any API call fires `mx:session-lost` and the gate re-checks.
- Routes (English since v0.8.1): `/` Home, `/new` Setup, `/game` Game (full screen, no nav), `/history`, `/history/:id`, `/stats`, `/players`, `/players/:name`, `/achievements` (`?player=` preselects a person), `/profile`, `/admin`; rooms `/r/:code` (join) and `/room/:code`. The old German addresses (`/neu`, `/spiel`, `/verlauf`, `/statistik`, `/spieler`, `/erfolge`, `/profil`, `/raum`, `?spieler=`) are mapped by `legacyPaths.ts` (`englishPath`, tested) and redirected — bookmarks, installed apps and shared room links carry them. Keep those redirects.
- Sign-in page: Google first, then „Mit E-Mail anmelden“ opens `auth/EmailAuth.tsx` (sign in / register / forgot, „check your inbox“, resend). `?register=1&name=` opens it in register mode — the `SignUpOffer` on `GameOver` sends online guests (no account on the device) there; Google is the other button. `/reset-password` (`ResetPasswordScreen`) is rendered by `AuthGate` whoever is signed in, and is excluded from the SW navigation fallback.
- `shell/AppShell.tsx`: bottom navigation bar (compact) / rail (≥ md) for five destinations — Spielen · Verlauf · Statistik · Spieler · Erfolge (the M3 maximum); the profile sits behind the avatar (top bar on phones, foot of the rail) and still counts as top level. Sub-pages use `SubPageHeader`.
- `auth/AuthGate.tsx`: the `loading` state renders outside `AnimatePresence`. With `mode="wait"` the empty loading frame had to finish an exit animation first, and roughly one load in ten never got past it (blank page, prod build too).

### State
- `GameContext` — mode, players, turn, current song, global timeline, played songs, skips, round options (`goal`, `decades`, `challengesEnabled`) and the turn state (`reveal`, `pending`, `finished`, `startedAt`, `rankingsHistory`). `rematch()` keeps players + options. **Persistence:** every change of a started, unfinished round is written to `localStorage.mxster_running_game` (`game/savedGame.ts`, max 3 days) and restored on start, so a reload resumes mid-turn without double credits; Home offers "Weiterspielen"/"Verwerfen". Reveal and pending placement must stay in the context for exactly that reason.
- `SettingsContext` also holds `recentSongs` (last 150 song keys, merged across devices) — `game/songPool.ts` draws fresh songs first.
- `GameHistoryContext`, `AchievementContext`, `SettingsContext` — stored on the server through `sync/useSyncedDoc.ts`: load once, debounced versioned writes, conflict → `sync/merge.ts` (history = union by id; achievements = unlocked wins, earliest unlock, max progress/stats; settings = local wins, saved players united). On an account's first load the old localStorage keys (`mxster_game_history`/`mxster_history`, `mxster_achievements`, `mxster_settings`) are adopted once, uploaded and removed. Saves wait until the document has loaded.
- Theme is additionally mirrored to `localStorage.mxster_theme` for the pre-paint script in `index.html`.
- `UIContext` — modals (keyed, `closeModal(): Promise`), toasts (optional `action`, e.g. undo).
- Achievements are keyed by **player name**; the account holder plays as his first name (`game/owner.ts`).
- **Achievement tracking** (v0.12.3): every change goes through the pure `game/achievementEngine.ts` (`applyAchievementEffects(doc, effects, now)` → new doc + newly unlocked; immutable, progress only grows, `add` counts up with `atLeast`). The context's `applyEffects` builds on a `latest` ref and `setDoc(prev => …)`, so a burst never overwrites itself (the old context wrote each change from the render snapshot: new people vanished, progress was lost). Rules in `game/achievementRules.ts`: `endOfRoundAchievements` (hardcore: the old rules; timeline modes from the turn log — decades, genres, a perfect round with ≥ 5 cards, fast wins, comeback via `wasLastEarly`), `historyAchievements` (streaks by `winner.name`, company, comebacks, bot wins by stored `level`), `roundCounters(person, games, round, points)` (rounds, wins, points and the `roundTally` counters — right cards, oldies < 1970, modern ≥ 2010, objections won, exact years, titles, artists — counted up, never below the stored rounds; the history keeps only 50). Since v0.12.7 `endOfRoundAchievements` alone judges a round, for every mode, from the turn log in play order (`rightSongs`: timeline — own right placement or won objection, first card left out; hardcore — guess within two years; streaks via `longestRun` in play order; never the player's year-sorted hardcore timeline). Wins need ≥ 2 seats (`wonStored` too). Since v0.12.6 the shared part (first round/win, team win, night owl 0–4 h, early bird 5–9 h, long round > 60 min, full house ≥ 6 people, perfect round ≥ 5 own songs all right, runs, objection won, decades in one round, 15 points, daily) runs in every mode; people are `peopleOf(players)` = players and team members, never bots. Rounds store `daily` (the day) for the daily achievements. `ICON_NAMES` lets a test check every achievement icon exists. Tests `game/__tests__/moreAchievements.test.ts`. `finishGame` applies them in every mode for people only (no bots, no teams). `components/AchievementBackfill.tsx` credits stored rounds once per visit, silently (`backfillAchievements`, hidden people skipped). Tests: `game/__tests__/achievementTracking.test.ts`, `contexts/__tests__/achievementBurst.test.tsx`, `useTurnFlow.test.tsx` „achievements“.

### Game loop (`src/game/`)
`useTurnFlow` is an explicit phase machine — `idle → placing` (timeline modes) / `guessing` (hardcore) `→ revealed → next turn | over`. Rules are pure modules: `placement.ts`, `guess.ts` (5/5/5-2-1), `skipRules.ts`, `achievementRules.ts`. Timeline modes credit a correct card on placement and check the win on continue; hardcore credits card + points on continue. **No draws:** if the end condition is met with a shared lead, `game/tiebreak.ts` runs a tiebreak ("Stechen") — only the tied players play, one song each per round in seat order, until exactly one leads after a full round; no skipping during it. State: `GameContext.tiebreak` (turn order honours it). Rankings share places for equal standings below the winner (`rankPlayers`, used by GameOver and history). Known gap: if all 211 songs are used up mid-tiebreak, `drawSong` returns null and the game cannot continue. Songs are drawn by a human tap (also for bots); bots then play through `placeCard`/`submitGuess`.

Round options and their rule modules (all pure, tested in `game/__tests__/roundOptions.test.ts`):
- `roundEnd.ts` — `isRoundOver(players, mode, goal)`; goal 5/10/15. Personal: anyone reaches the goal (a challenge can put a card on someone not on turn).
- `songPool.ts` — decade filter (empty = all), no repeats within a round, recent songs avoided; widens to all decades instead of stalling.
  Exotics (`song.exotic`) are out unless the round option `exotics` is on (`catalogue()`); they are the last resort only after every well-known song is used up (toast says so).
- `challenge.ts` — Einspruch: 3 per player/team per round, timeline modes only, never by bots, not on a first card, not in a tiebreak. Flow phase `challenge` (`pending` in context): `startChallenge(seat)` → `claimGap(gap)` or `revealPlacement()`. Placer right → placer gets the card; placer wrong + challenger right → challenger gets it (own timeline / credited on the shared one); the objection is spent either way.
- `teams.ts` — a team is a `Player` with `members` + `memberTurn`; `NEXT_TURN` advances the member. Achievements are never credited to teams. Teams from 4 people, no bots.

Board: `components/game/TimelineBoard.tsx` + `PlacementDock.tsx` — the dock card and the card on the board share a layoutId **per song** (`pendingCardLayoutId(song.id)`). Never a constant id: the card revealed last turn stayed registered under it, and when the next card was placed Motion hid the old one (opacity 0, stacked behind) — the board looked empty exactly when someone wanted to object (pinned in `layoutIds.test.ts`). Placement flow: (drag or tap a gap → preview → confirm; `game/boardGeometry.ts`). **Never render the year of a pending card.** Where a waiting card sits: `PositionStrip` in the dock (confirm, objection offer, objection confirm) draws `[year before] — [?] — [year after]` in the poster type (`früher`/`später` at the ends, years blurred with „Jahre verdecken“, the `gapLabel` sentence is its accessible name); on the board the two neighbours' year chips take the slot's colour (primary for the placed card, tertiary for an objection preview) and the waiting card shows a poster „?“. A wrong card's result names where it belonged (`correctGapIndices` → "Richtig wäre: …").

Mobile placing (below `lg`, 1024 px):
- While a song is on the platter the `Turntable` renders `compact` — a sticky bar under the header (small record, whose turn, progress, play/pause). It is the same component instance, so audio is untouched; the record is a shared element (`layoutId="turntable-record"`). The left grid column is `max-lg:contents` so the bar can stick across the board.
- When placing (or objecting) starts, the page scrolls the board right under the sticky bar.
- One drag physics for both start points: `game/useCardDrag.ts` (measure gaps on grab, edge auto-scroll, hover via `computeInsertionIndex`, tilt, haptics). The dock card (`DragStage`) and the waiting card on the board (`TimelineBoard` `PreviewRow`, also the objection preview) both use it. The waiting card carries `data-gap-index` of its own gap (`home`), so dropping it there or away from the board springs back and never highlights its own slot; another gap calls `onPreviewMove` → `setPreviewGap` (local, online too — only confirming sends an intent). The row is keyed per song, not per gap, so it glides to the new gap as one element. The auto-scroll bottom edge is the dock (`[data-dock]`). Spring-back values: `dragReturn` in `motion/springs.ts`.
- Drag auto-scroll: the card starts inside the dock, i.e. inside the bottom edge zone — scrolling is only armed after the card has left the dock, never while it is over the dock, and only after it rests 350 ms at an edge (aiming at a gap right above the dock must not run the page away). Edges are measured from our own element ref: Motion's `onDragStart` event target is a window-level node, `event.target.closest()` finds nothing.
- Autoplay blocked (always after a reload on phones): the player waits `paused`, starts on Howler's next `unlock` (first tap), and the bar says "Zum Abspielen tippen" with a pulsing play button — no toast.

### Multiplayer (online rooms)
**The host's device runs the game, the server only relays.** No game rule exists in Python.
- **Server** (`server/app/api/rooms.py`, `rooms_hub.py`, `friends.py`): tables `rooms` (status lobby → running → finished/closed, music `room|everyone`, options, latest snapshot + `rev`, expires 12 h after the last activity), `room_members` (seat; account `user_id` or guest name + **hash** of the seat token), `friendships` (one row per pair, a < b, pending until the other side accepts), `room_invites`. Codes: 8 chars Crockford base32, typing is forgiven (case, dashes, I/L→1, O→0). Max 10 seats, no new joins after the start, rejoining one's seat always works while the room is open, the host may remove people in the lobby.
- **Guests**: `POST /api/rooms/{code}/join {name}` without a session sets the httpOnly cookie `mx_guest` (signed `{room code, seat token}`, 14 h). `audio-check` lets a guest through while their room is `lobby|running` — that is how guests hear the music. A guest cookie only ever opens its own room.
- **WebSocket** `/api/rooms/{code}/ws`: auth by session or guest cookie, `Origin` must equal `PUBLIC_URL` (missing Origin is refused), one socket per seat (a new one replaces the old with close code 4000). Messages: host → `state {snapshot}` (stored, `rev`+1, relayed) and `audio {songId, playing, positionMs}` (server stamps `at`), players → `intent {action,…}` (server overwrites `seat` with the sender's real seat and hands it to the host only; `host_offline` error if the host is not connected), everyone → `ping` → `pong {t, server}`. Seats are re-checked on state/audio/intent at most every 10 s (`RECHECK_S`) — a blocked account, signed-out session or kick loses the socket. **One uvicorn worker is a hard requirement** (the hub lives in memory).
- **nginx**: `location ^~ /api/rooms` — **no trailing slash**, with one nginx answers `POST /api/rooms` with a 301 and creating a room fails — with `Upgrade`/`Connection $connection_upgrade` and `proxy_read_timeout 1h`, before `/api/` (`server/deploy/nginx-locations.conf`; the `map $http_upgrade $connection_upgrade` exists in the VPS http block).
- **Client** (`pwa/src/online/`): `roomClient.ts` (reconnect with backoff 0.5–8 s, intents queued while offline, snapshots never; clock offset = median of the last 5 pings, `clock.ts`), `RoomContext.tsx` (room, seat, role, members, cue; players load every snapshot via `LOAD_GAME_STATE`; the host loads the room's snapshot once when it connects, so a reload or another device continues), `rules.ts` (`mayAct` — who may draw/place/guess/skip/object/claim/reveal/continue; the host may also draw, reveal and continue for anyone), `useHostBridge.ts` (host: debounced snapshot on every state change, intents checked with `mayAct` + gap range, then the same flow functions the local controls call), `useRemoteTurnFlow.ts` (players: same shape as `useTurnFlow`, every action is an intent). `game/deriveTurn.ts` is the shared pure phase derivation.
- **Objection window online** (`game/objectionWindow.ts` pure, `online/useObjectionWindow.ts` on the host's device): `pending.passed` (player indices that tapped „Kein Einspruch“, intent `pass`, flow `passChallenge`) and `pending.deadlineAt` (server ms, `OBJECTION_WINDOW_MS` = 10 s, set by the host via `setObjectionDeadline`). The host's device opens the window and turns the card over once `waitingOn` is empty (all passed, or away) or the deadline passed; while someone is choosing a gap the deadline times that choice (`CHOOSE_GAP_MS` = 30 s, then the host drops the objection). Dropping an objection (`cancelChallenge`, by hand or by timeout) counts as „Kein Einspruch“ for that person on this card (no second objection) and gives the others a fresh countdown — nobody can hold a round by objecting and dropping in a loop. The `reveal` intent is refused for everyone online (`mayAct`); on one device the reveal button stays (the table decides). Every device shows „Aufgedeckt wird in N s“ from the server clock. Presence no longer reveals for an absent placer (the window does).
- **Step clock online** (`game/turnClock.ts` pure, `online/useTurnClock.ts` on the host's device, `GameState.stepClock {key, at}` in the snapshot): every step has a limit so a connected but inattentive player cannot hold the round — draw 30 s (then drawn for them), place/guess as long as the song plays and 30 s after it ended or was paused (`placingAt`, follows the room's audio cue; never more than `PLACE_CAP_MS` = 6 min from the draw; then the turn lapses via `passTurn`, no card). The music device also reports when a song ends; the sender keeps its own cue (`sendAudio` sets it locally) and the Turntable holds `onCue` in a ref — reporting on a new `onCue` identity looped once (every report is a new cue), after the reveal 20 s (then `continueTurn`). The key (`stepKey`: phase, player, song, turn count, songs drawn) makes every step a new clock. Absent players are left to presence (no double action). All devices show the last 30 s as a pill top right (`role=timer`, red from 10 s). Objections keep their own clock.
- **Host rights online**: the host may draw and continue for a player only when that player is away (not connected, left, or absent — `TurnView.away`, computed in GameScreen from the roster and `absent`); otherwise everyone acts for themselves.
- **Objection online**: the challenge-offer dock gets `online` + `ownCard`. Each device only lists its own seat (filtered with `isMine`), shown as a plain „Einspruch einlegen“ button with the remaining dots — no name (on one device the name chips stay: there the name says who objects). The placer's device shows „Die anderen können jetzt Einspruch einlegen.“ The rules were always right (`eligibleChallengers` excludes the placer, `startChallenge`/`mayAct` check it); only the label misled.
- **Game screen**: `GameRound` (exported, used by `/game` and `RoomScreen`) asks `can(action)` for every control; other devices show waiting text (`DockState 'waiting'`, `continueBy`, `revealBy`, `rematchBy`). Online rounds have `GameState.onlineRoom` set and are **never** written to the device's saved game. Player seats: `Player.seat` (not equal to the index once someone was removed), `Player.guest`.
- **Music**: `Turntable audioRole` — `host` plays and reports every start/pause and every 4 s; `follow` ("Jeder bei sich") plays from the cue and re-syncs every 2 s when more than 250 ms off (measured locally: ~20 ms apart, pause/resume within one check); `silent` plays nothing and shows the position of the device that has the music. "Gemeinsam im Raum": the music device is the device of whoever is on turn (`online/musicSeat.ts`, pure; falls back to the host when that seat is not connected, absent, left or unknown) — that device gets role `host` (plays + reports the cue), all others `silent` (caption „bei <Name>“). The role can change in the middle of a song: the Turntable stops when it hands over and continues from the last cue when it takes over (paused stays paused). The server accepts `audio` from any seat when the room's music is `room` (silent devices only display a cue), only from the host for `everyone`. Verified with two browsers: only the device on turn requests the audio file, positions agree, the host takes over at the same position when the player's page closes.
- **Routes**: `/r/:code` (join: account one tap, guest name; "Mit Google anmelden" remembers the room in `localStorage.mx_pending_room` and Home sends the user back), `/room/:code` (lobby with QR code — `qrcode-generator`, dark on white whatever the theme — link, members with online dot, kick, friend invites; then the round). Both outside `AppShell`. `AuthGate` lets anyone who is not approved onto these two paths only, wrapped in `SyncModeProvider mode="guest"`: account documents stay in memory, no request asks for an account.
- **Order and freshness of intents**: `intentHandler` (useHostBridge) runs each intent inside `flushSync`, so the next one is checked against the state the previous one left (two taps can never both pass: reveal + objection, continue twice, reveal twice). `NEXT_TURN` always clears `pending`. Intents tapped while the own socket is down are delivered only if it is back within `QUEUE_MAX_AGE_MS` (3 s). On a player's device the placed card stays in its gap with „Wird übermittelt …“ until the host's state arrives (6 s timeout gives the controls back).
- **Host reload**: the stored snapshot is blind (year 0); on its welcome the host's device puts the real song back from the bundled list (`restoreSong`), otherwise a placement would be judged against year 0.
- **What crosses devices is checked** (`online/sanitize.ts`): before the reveal the snapshot carries the song on the platter **without year, album and fact** (`blindSnapshot`; the bundled song list still holds every year — this keeps the answer out of the live traffic only). A player's device stores the host's result only after `sanitizeResult` (known mode, winner among the players, max 10 players / 60 cards / 400 turns, strings cut, unknown fields dropped).
- **Presence** (`game/presence.ts` pure, `online/usePresence.ts`): the roster carries `online` and `left` per seat. On the host's device `useHostPresence` notes when a connection drops (local clock) and after `AWAY_GRACE_MS` (30 s) puts that player into `GameState.absent` (player indices, travels in the snapshot); `nextSeat` skips absent players (also in a tiebreak, where a skipped contender counts as played). When the round waits on an absent player, `unstick()` names the step and the host takes it once per situation (`passTurn` — no booking —, `cancelChallenge`, `revealPlacement`, `continueTurn`). Absent or gone players are never offered an objection. The host is never absent. `usePresenceNotices` (every device) toasts lost/back/left/skipped; players' devices show a banner while the host is offline.
- **Leaving**: `POST /api/rooms/{code}/leave` (account: CSRF; guest: cookie, then deleted). Lobby: seat deleted. Running: `room_members.left_at` set — the seat stays for the results, the socket is closed (`closed`/`left`), `/join` answers 409 `left_round`, the WebSocket refuses it (4003 `left`), a guest loses `/audio/`. The host gets the roster and `markLeft()` sets `Player.left`: out of turns and objections, never the winner (`leadersAmong(stillIn())`), dropped from a tiebreak, listed last without a place on the result screen, not in a rematch. Only one player left in → that player wins. The host cannot leave (closing the room is the host's way out). `left_at` is added to existing databases by `_add_missing_columns()` in `db.py` (create_all never alters tables).
- **Results**: the host's flow saves the round as before; account players save the sanitized result into their own history when the final snapshot arrives (`useSaveOnlineResult`), guests save nothing. Achievements are still tracked on the host's account only (per name, like on one device).
- **Friends** (Spieler tab, `FriendsSection.tsx`): search by part of the name or exact e-mail (approved accounts only, never returns e-mails), request/accept/decline/remove, incoming count badge. Invitations show on Home (polled every 30 s and on focus).
- Setup and a running round: `SetupScreen` sends anyone with a running round on this device back to Home (continue or discard there) unless Home passed `state.newRound` after asking. `keepOptions` never carries the daily round's options over.
- Setup persistence: `SetupScreen` writes mode + round options to `mxster_last_mode`/`mxster_last_options` on every change (effect gated by `hydrated`, set together with the restore, so the first render never stores the defaults); a restored „nemesis“ falls back to all songs when there are fewer than `NEMESIS_MIN` misses. Lobby bots/difficulty/teams: `sessionStorage mxtape_lobby_<code>`. Test `screens/__tests__/setupPersistence.test.tsx`.
- Setup: "Wie sitzt ihr zusammen?" one device / own devices; own devices hides players, bots and teams (bots and teams are set in the lobby, see v0.12.0) and asks for the music mode.

### Start points (v0.11.0)
- `scripts/audio-hosting/start-points.js` measures RMS in 0.5 s windows (ffmpeg astats; the metadata goes to stderr) and stores `startMs` = first point at median − 10 dB held for 1.5 s (0 under 1.5 s, max 40 s). −6 dB skipped whole verses. 242 songs have one (mostly music-video intros). `add-song`/`exchange-song` compute it automatically. `Turntable.startPosition(song, random, rand)` starts there, or randomly between it and 150 s.

## Design System — Material 3 Expressive ("vinyl magenta", v0.4.0)

**Single source of truth: `pwa/src/styles/design-tokens.css`.** Nothing outside it holds raw colour (exceptions: the pre-paint loader in `index.html` and `THEME_COLOR` in `SettingsContext`, both mirrors).

- **Colour**: the reference palettes are **generated** by `pwa/scripts/gen-tokens.mjs` from `SEEDS` (primary `#C2185B` magenta, tertiary `#FF8A3D` amber, neutrals = primary hue at chroma 6/12) into the `BEGIN/END GENERATED PALETTES` block. Values are RGB triplets so Tailwind alpha modifiers work. Roles (dark default + light) reference tones by name. Extra brand tokens: `--mx-brand` / `--mx-on-brand` (saturated fill with white text for the few hero actions, `.btn-brand`), `--mx-vinyl`, `--mx-groove`, `--mx-label`, `--mx-label-2`. Only the `md-*` Tailwind namespace exists (legacy aliases were removed).
- **Colour schemes** (v0.12.8): `scripts/gen-tokens.mjs` holds `SCHEMES` (primary, tertiary, data seed each; first = default `vinyl`, unchanged values) and `FIXED` meaning colours (error, success, warning — the same in every scheme). It writes the default palettes into `:root` and one `[data-color='<id>']` block per other scheme (primary, secondary, tertiary, neutral, neutral-variant, data — surfaces are tinted with the scheme's hue), `src/styles/colorSchemes.ts` (ids, swatches, surface/label/vinyl per theme) and the `MX_SCHEMES` map in the index.html pre-paint (between markers). Before writing it checks every scheme: M3 text pairs ≥ 4.5:1 in both themes, white on the brand fill, accents ≥ 25° from success and ≥ 15° from error, primary ≥ 20° from warning, the three chart series ≥ 40° apart — a failing seed is refused (`npm run tokens:check`, also run by the vitest suite). Setting `Settings.color`, mirrored to `localStorage.mxtape_color`; `applyAppearance(theme, color)` sets `data-theme`/`data-color`, storage and the theme-color meta. Picker `components/ui/ColorPicker.tsx` (radiogroup, arrow keys) in Profile → Darstellung; the change uses the theme's circular reveal (`revealChange`). index.html no longer sets a page background (it was unlayered and beat the app's CSS); the loader carries its own, in the stored scheme. App icons stay magenta.
- **App icons**: the same record, generated by `npm run icons` (`pwa/scripts/gen-icons.mjs`: SVG sources → headless Chrome PNGs → `favicon.ico`). Small sizes use a simplified disc with a larger label; maskable and touch icons put the record on a brand-magenta tile.
- **Signature element**: the record (`components/ui/Vinyl.tsx`) — grooves + label rotate via CSS (`.vinyl[data-spinning]`, pauses in place), the sheen is a static layer on top. Used on the login screen, the home "Neues Spiel" sleeve, the turntable (label = play/pause, then the revealed year coloured by verdict), waiting room, game-over. Keep everything around it quiet.
- **Backdrop** (`components/ui/Backdrop.tsx`, CSS section "Backdrop" in `tailwind.css`, mounted once in `App.tsx` outside the sign-in gate): five fine sound waves along the lower 40 % of the screen, faded towards the top. **Not a record** — the record stays the one signature element. Each wave is an SVG of two periods (harmonics are whole numbers, so it repeats exactly; pinned) sliding left by half its width at its own speed (70 s + 17 s per wave). While music plays (`html[data-playing]`, set by `Turntable` through `hooks/useBackdropPlaying.ts`, counted so two players never clear each other) the group swells and pulses gently (scaleY). Only transform moves. Line strength `--mx-wave-{ink,brand,warm}-alpha` per theme. Reduced motion: still image. ⚠️ `body` must not paint a background (`html` carries the surface), and the nav rail is transparent — otherwise they cover the z-index -1 layer.
- **Record drawing** (`Vinyl.tsx`): ~40 fine grooves with varying opacity and three track gaps, a lead-in rim, label gloss, spindle shadow; the static sheen is a groove-masked `conic-gradient` (`.vinyl-sheen`) with a faint magenta/amber tint — no hard-edged wedges.
- **Type**: Roboto Flex variable, **self-hosted** (`pwa/public/fonts/*.woff2`, full wdth 25–151 axis). `.text-poster` = wide + heavy (`wdth 140, wght 860`) for the wordmark and hero moments.
- **Components** (`styles/tailwind.css`): `.btn` (+ `-brand/-filled/-tonal/-outline/-text/-danger`, `-lg`), `.icon-btn`, `.surface`, `.row`, `.field`, `.chip`, `.meta`; radius encodes hierarchy (hero xxl, sections xl, rows lg, chips full). Elevation is tonal.
- **Haptics** (`utils/haptics.ts`): `haptic(kind)` with fixed short patterns (`grab` 8, `tick` 5 throttled to one per 60 ms, `drop` 10, `success` [12,50,18], `miss` 28, `win` [15,60,15,60,30] ms). Silent without `navigator.vibrate` (iPhones), with a fine pointer (desktop) or when `Settings.haptics` is off (default on; mirrored into the module by `SettingsProvider`; the profile switch only shows on devices that can vibrate). Used for history row → round page and player avatar → player page. The theme reveal still wins (its rules come later in the file). Reduced motion: plain 120 ms cross-fade.
- **Skeletons** (`components/ui/Skeleton.tsx`, `.mx-skeleton` in `motion.css`): history and statistics show placeholders shaped like the content while the account document loads; they appear only after 250 ms and shimmer (transform only, still under reduced motion). `.stagger-children` builds up statistics and profile.
- **Motion**: `src/motion/springs.ts` is the single source (M3 specs → Motion springs + generated CSS `linear()` block; `UPDATE_SPRING_CSS=1 npx vitest run springs` after changing a spec). Spatial springs may overshoot, effects never. One reduced-motion policy (`motion/policy.ts`). Only `m.*` components (LazyMotion strict). Routes animate with View Transitions (`useAppNavigate`, `NavLink viewTransition`), never with Motion; persistent chrome has `view-transition-name` (`nav-bar`, `nav-rail`, `top-bar`), the home sleeve and the setup page share `new-game` (container transform). During the theme reveal all names are dropped (`html[data-theme-transition] *`).

**Gotchas (all hit while building v0.4.0):**
- Motion owns `transform` on an `m.*` element — Tailwind `translate-*` classes on the same element are silently overwritten. Position on a plain wrapper, animate inside.
- StrictMode replays effects: one-time setup (e.g. prefilling the owner in `SetupScreen`) needs a ref guard, or players double up.
- The Playwright MCP browser sometimes resets the viewport after `navigate`; resize again before screenshots. Full-page screenshots show sticky headers in the middle — judge layout from viewport shots.
- Vite HMR full reloads trigger the game's `beforeunload` dialog in dev.
- `.m3-dialog-panel` is a surface only; CSS entrance in `.m3-dialog-enter`. Never combine CSS keyframes and Motion on one element.
- `<Modal>` content is a prop snapshot; `closeModal()` resolves on exit; history-back popstate is async (one global listener swallows self-caused pops).
- Tests: wrap `m.*` in `test/MotionTestProvider`; `test/setup.ts` installs `test/fakeApi.ts` as `fetch` (in-memory `/api/data` with versioning) — stub `fetch` yourself for other endpoints (`vi.stubGlobal`).
- After changing `tailwind.config.js`, restart the dev server.

## Best Practices
- Song type: `export const songs: Song[] = [...]` (the integrity test parses it with `/export const songs(?:: Song\[\])? = (\[[\s\S]*\])/`).
- Song data is maintained without Spotify: `lib/musicData.js` (MusicBrainz year + original album — only recordings credited to exactly that artist, no compilations/live/DJ mixes; Cover Art Archive, iTunes as fallback), `lib/songStore.js` (the only writer of songs.json/song-facts.json; regenerates songs.ts through sync — writing songs.ts directly drops every fact), `lib/songWizard.js` (shared add/exchange flow; refuses a year-spoiling fact; duplicate check ignores case/accents). The lookup is a suggestion — MusicBrainz misses originals sometimes (Bohemian Rhapsody comes back as 1976), so the wizard shows all candidates and asks for the year. yt-dlp runs with an argument list (titles with quotes are safe) and warns on lengths outside 1:30–10:00. Songs without a fact are fine (only confident facts, never the year).
- Adding many songs at once (done for v0.10.2): run `add-song.js` per song with `--year --genre --yes --no-upload` and an explicit `--album` from a separate MusicBrainz lookup with pauses (MusicBrainz answers 503 under load, and add-song then silently falls back to iTunes, which often returns a best-of or a sampler). Afterwards: compare every year with MusicBrainz (MusicBrainz often reports a later reissue — Hound Dog 1969, Believe 1968 — so judge each case; an album track released as a single later takes the album year, like Wonderwall 1995), check albums for compilations, and look at all new covers on one contact sheet (`magick montage -font …/Arial.ttf -label '%t' …`) — wrong covers (soundtracks, lullaby covers, casting-show versions) are only found by looking. Then rsync audio + covers, `npm test`, deploy web.
- Touch targets ≥ 48 px; `hoverOnlyWhenSupported` is on, so `hover:` never fires on touch.
- UI copy is German, sentence case, active verbs; **no emoji anywhere** — every symbol is an inline SVG from `components/ui/Icon.tsx` (achievements map to icons via `achievementIcon(id)`; stored achievements may still carry old emoji strings, so never render `achievement.icon` from stored data directly).
